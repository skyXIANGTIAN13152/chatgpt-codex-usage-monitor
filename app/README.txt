迪迦额度显示器 v2.0.0

打开方式
完整解压便携包，双击 TigaEnergyMonitor.exe，直接出现桌面小悬浮窗。
这一版将迪迦本体抠出，人物与信息直接浮在桌面，没有壁纸底板或矩形外框。
布局占用 420×246，可选 80%、100%、125%、150% 缩放；透明空白区域可以穿透到桌面。
未登录时，点击浮窗中的 ChatGPT / Claude Code 登录链接。
拖动迪迦可移动；位置自动保存。默认置顶，不占任务栏。
底部工具始终显示；从左至右为刷新、暂停动画、置顶、设置、收进托盘，鼠标移开不会自动隐藏。
账号信息与底部工具按实际内容紧凑排列；隐藏账号后自动上移，腾出的透明区域可穿透到桌面。
也可直接右键人物打开设置。
设置单独打开，关闭设置后仍保留悬浮窗；托盘单击恢复浮窗。
无需启动 Codex / ChatGPT 桌面应用，也不需要运行 Steam 或 Wallpaper Engine。
首次启动不会自动沿用旧应用的账号；请在你选择的官方登录页面完成授权。

功能
• Codex 与 Claude Code 的显示开关彼此独立，可以只显示一个、两个都显示或全部隐藏。
• 设置中的“显示目标”可选择 Codex、Claude Code，或选中的应用聚合结果来决定迪迦状态；与账号明细的显示开关独立。
• 迪迦状态优先使用五小时剩余；目标没有五小时限制时才使用总周。聚合按应用等权平均、分别计算同周期额度，同样优先五小时。已声明的五小时额度过期或缺值时等待同步，不回退到总周。浮窗只保留人物与额度信息，来源选择放在设置中。
• Codex 常态蓝青、低于 50% 时玫瑰到血红；Claude Code 常态白到亮黄、低于 50% 时深黄到橙红；真实 0% 均使用石灰封印色和粉尘。
• 低额度的条与环使用金属反光和窄边高光；各周期独立生效，满能量、石化和待同步保持各自材质。
• Codex 的 ChatGPT 官方登录、退出和额度读取；账号存放在独立目录。
• Claude Code 使用随附的未修改官方程序登录，再尝试从官方 /usage 用量界面读取额度。
• 三态人物轮廓固定，保留原动态光效；移除满能量的全身摇动位移，默认以 1.8 秒交叉淡化切换。
• 动画预览与真实额度分开。点击三种状态只预览画面，不会改变账号数据。
• 无边框小悬浮窗、窗口置顶、记住位置、缩放、暂停动画、减少动态效果、红灯阈值。
• 字体加粗；每个账号的五小时、总周数字和条形颜色按各自真实额度独立判断，预览、聚合目标和迪迦红灯阈值不会给其他周期染色。
• 减少动态效果时使用静态画面并关闭过渡；播放按钮始终可以点击，手动播放可覆盖系统或应用的静态偏好。
• 设置中的“随 Codex 启动”“随 Claude Code 启动”可单独或同时开启，默认关闭。
• 设置中可在“光能条”和“光能环”之间二选一，默认光能条，选择会自动保存；两种图形不会同时显示。
• 两种形式均保留旧版双周期规则：总周对应左侧光能条或外圈，五小时对应右侧光能条或内圈；每周期独立告警，缺周期自动收为单条或单圈。
• 光能条与光能环均显示各账号自己的额度。环位于账号信息旁，每个账号一个环组；外环总周、内环五小时，只有一个周期时显示单环。中央优先显示五小时百分比，两周期数字、重置与刷新提示均保留。

自动启动
开启任一“随应用启动”选项后，一个轻量本地监视器会在登录 Windows 时启动。
它检测对应软件的启动并打开本显示器，排除显示器自身的后台组件，避免循环启动。
关闭对应软件不会关闭显示器。关闭两个开关即可取消本显示器的自动启动监视。
浮窗的横线按钮或人物双击收起到托盘；完全退出请右键托盘图标，选择“退出额度显示器”。

额度与能量
在设置的“显示目标”中选择 Codex、Claude Code 或聚合模式。默认使用 Codex；升级前仅显示 Claude 的用户默认使用 Claude。
单应用模式优先使用该应用的五小时剩余，没有五小时限制时才使用总周。聚合模式可勾选应用，每个应用权重相同，控制周期也按五小时优先。
例如两家五小时剩余 80% 和 20%，聚合为 50%；每周剩余 40% 和 80%，聚合为 60%，因此用 50% 判断状态。
总周额度只使用应用总额度，Sonnet、Opus 等模型专属限制单独留在完整明细中，不会混算为总周剩余。
两家额度单位不同，聚合值是剩余百分比的平均，不代表可以转移或兑换的共享额度池。
控制周期缺少任一所选应用的有效额度时，迪迦状态等待同步，不会跳过该应用计算平均值。非控制周期暂缺或过期不会阻挡有效的五小时结果，各账号明细仍独立标注待同步。
显示/隐藏账号明细不会改变显示目标。默认剩余 20% 或以下为红灯，0% 石化。
没有登录、没有额度数据、数据超过 3 分钟或已经到重置时间时，不会猜测为 0% 或 100%。
暂停动画只暂停画面，额度仍会刷新。减少动态效果时显示静态画面并关闭过渡。
只显示官方返回的额度窗口，不保证所有账户都有相同的五小时/每周窗口。
浮窗优先显示“总周”和“5小时”，每个周期独立告警；鼠标悬停可看剩余、重置倒计时、当地重置时间及刷新年龄。
账号旁和底部显示“刚刚刷新 / N秒前 / N分钟前刷新”；聚合按所选应用中较早的成功刷新计算。
全部模型额度明细在设置的“账号与完整额度”中查看；缺少周期不会填造额度。

验证范围与限制
已验证独立启动、两套原版官方组件在全新目录下的未登录状态、小悬浮窗和独立设置窗口、显示选择与缩放、真实视频播放和平滑切换及后台自动化测试。
未替你完成真实账号登录，真实授权后的完整读数需要你登录后验证。
Claude 的用量读取为实验性集成：官方没有独立的订阅剩余额度 JSON 查询命令，这里通过原版 CLI 的 /usage 界面读取。
首次官方设置、账号权限或上游界面变化可能使 Claude 显示“等待同步”；此时提供官方用量页及需要时的“完成官方首次设置”入口。
不会把未读到的数据填成演示额度。此版本尚未代码签名。

复用情况
原来的 1.0.6 项目保留在原位置。
这一版原样复用旧 C++ JSON 解析、额度解析、多额度桶选择、稀疏数据合并和能量状态逻辑，并保留对应核心检查。
启动监视器复用旧版进程枚举和可执行文件路径读取代码。
新的登录流程、Claude 适配、前后端通信边界及动画界面是本次新增代码。
新界面使用 Electron 播放透明人物视频；随包包含两套官方命令行组件，因此便携包较大。

数据位置
应用独立设置与账号目录：%LOCALAPPDATA%\TigaEnergyMonitorV2
仅迁移旧版的刷新间隔、红灯阈值和置顶偏好。没有复制旧账号凭据。

素材
壁纸作者：柊明；三套素材对应 Steam Workshop 3778523054、3778488689、3778530158。
原始场景通过原生引擎录为 800×600、30fps、14秒无声循环，来源见 resources/app/ui/assets/scenes/manifest.json。
新版人物用内置 imagegen 从原壁纸画面提取透明图，移除城市、天空、地面，保留贴身光晕。
工具提取会对人物细节作一定重建；透明人物结合原视频光效，三态不添加几何位移；满能量先前的 shake.frag 位移已移除。
满能量循环为 14.5 秒，红灯/石化为 14 秒，均为 800×600、30fps。石化只加强原环境灰度流光，不添加发光能量。
原素材本身画面外的身体部分不补绘，画面底部以透明渐隐消除截断感。
透明素材与合成记录见 resources/app/ui/assets/characters/manifest.json；完整提示词见同目录 imagegen-prompts.json。
托盘图标为本次通过内置 imagegen 生成的候选图标，制作说明见 ASSET-NOTES.txt。

源码重建
源码包包含本次界面、后端、原 C++ 核心、启动监视器及测试。
安装 package.json/pnpm-lock.yaml 中固定的开发依赖；安装 backend/claude-runtime 的固定依赖。
原生组件需要 Windows x64、MSVC C++ 工具及 Windows SDK、CMake 3.25 或更新版本。
打开“x64 Native Tools Command Prompt for VS”，确保 cmake 和 ctest 在 PATH 中，从源码根目录依次运行：
  native\core-helper\build.cmd
  native\launch-watcher\build.cmd
两个脚本会配置、构建并运行各自的 CTest 检查，生成 runtime/monitor-core.exe 与 runtime/tiga-launch-watcher.exe。
也可显式设置 TIGA_TOOLCHAIN_ROOT 使用已有工具链包；该目录应包含 msvc/setup_x64.bat，以及 cmake-*-windows-x86_64/bin 下的 CMake 与 CTest。未设置时使用当前开发命令环境，不依赖任何固定磁盘路径。
官方 Codex / Claude 与 Node 运行时可从同版本便携包 resources/app 的对应目录复制。
在源码根目录运行 node --test tests/*.test.cjs；node tests/ui-e2e.cjs 验证实际窗口。
node scripts/package.cjs <目标目录> 生成便携目录。UI 测试使用独立数据，不需要或触发真实登录。
源码及构建脚本沿用 MIT 许可证；角色、壁纸和其他素材不包含在 MIT 授权中，第三方组件分别适用其原有许可与条款。
